# 拼音首字母检索方案（暂不实施）

目的  
在“报名管理”的学员姓名检索中支持拼音首字母输入（例如：输入 `z` 匹配“张大力”，输入 `zd` 进一步缩小），并兼容中文姓名与手机号检索。

状态  
仅为方案记录，当前不落地实现。

推荐方案（后端 + 数据库，稳定可扩展）
1) 数据库字段  
- 表：`sys_users`  
- 新增：
  - `nick_name_pinyin`（全拼，如 `zhangdali`）
  - `nick_name_initials`（首字母，如 `zdl`）
- 为上述字段加索引，保障检索性能。

2) 写入时自动生成  
- 新增/编辑/导入学员时，根据 `nick_name` 生成拼音与首字母并写入。
- 可以使用 Go 拼音库在后端统一处理，避免前端重复计算。

3) 查询规则（建议）  
输入内容判定：
- 纯数字：按手机号 `phone LIKE '176%'`  
- 含中文：按姓名 `nick_name LIKE '%张%'`  
- 纯英文：按拼音或首字母
  - `nick_name_pinyin LIKE 'zd%'` 或 `nick_name_initials LIKE 'zd%'`
- 混合输入：按优先级分流（数字优先，其次中文，最后英文）。

4) 存量数据回填  
- 增加一次性脚本，对已有 `sys_users.nick_name` 批量生成并填充拼音字段。
- 建议分批执行，避免长时间锁表。

5) 前端改动  
- 不必新增 UI，只需继续使用现有搜索框；后端根据输入类型做分流。
- 可选：输入框提示“支持中文 / 拼音首字母 / 手机号”。

非推荐方案（仅前端过滤）
- 在前端用拼音库对“当前页数据”转拼音再筛选。
- 缺点：分页后不准确；数据量大时性能差。

风险与规避
- 多音字不准：允许手动修正或接受默认拼音。  
- 回填锁表：分批/低峰执行。  
- 性能：加索引、避免全表扫描。  
- 兼容性：查询逻辑保留原中文/手机号检索作为回退。

实施步骤（建议分阶段）
1) 仅新增字段与索引（不改搜索逻辑）  
2) 回填存量数据  
3) 更新搜索逻辑支持拼音  

待确认问题
- 仅“报名管理”需要？还是“师生管理”等也需要？  
- 支持“首字母”即可，还是“首字母 + 全拼”都支持？
